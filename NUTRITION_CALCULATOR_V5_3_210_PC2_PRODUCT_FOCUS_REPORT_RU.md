# Отчёт Product Focus & Editorial Stabilization

## Резюме

PC2 закрывает остаточную проблему после PC1: корректный, но всё ещё слишком длинный результат. Вместо одновременного предъявления всех методик пользователь сначала получает короткий набор практических приоритетов, а затем по выбору открывает питательные итоги или качество рациона.

## Новая иерархия результата

### Уровень 1 — краткий фокус

Показывается не более пяти пунктов. Каждый пункт содержит:

- действие или вывод;
- короткое объяснение;
- источник приоритета: персонализация, КБЖУ, HEI или сценарий ввода.

### Уровень 2 — питательные итоги

Содержит существующие расчёты энергии, макронутриентов, клетчатки, витаминов и минералов. Расчётная логика не изменена.

### Уровень 3 — качество рациона

Содержит HEI и структурные рекомендации. Уровень доступен только после явного подтверждения, что введён полный день.

## Логика приоритетов

- сначала сортируются отклонения с большей выраженностью;
- одинаковые по смыслу формулировки дедуплицируются;
- результат ограничивается пятью пунктами;
- при отсутствии явных отклонений показывается нейтральный вывод без искусственного поиска проблемы;
- при неполном вводе не формируется финальная оценка питания.

## Поиск

Редакционный слой поиска расширен с нескольких запросов до набора наиболее вероятных бытовых намерений. Базовые продукты получают преимущество перед брендированными товарами, рецептами и готовыми блюдами, когда запрос состоит из одного общего слова.

Это не означает, что база уже прошла ручную редактуру по всем 1105 карточкам. PC2 улучшает первый результат для типовых намерений и создаёт основу для последующей проверки по реальным поисковым логам.

## Product impact

PC2 изменяет:

- порядок предъявления результатов;
- краткий пользовательский вывод;
- навигацию между аналитическими слоями;
- редакционное ранжирование поиска;
- плотность поисковых карточек в простом режиме.

PC2 не изменяет:

- исходные нормы;
- нутриентные значения продуктов;
- формулы;
- protected-mode safety policy;
- статус внешней валидации.

## Ограничения

Автоматические и browser-тесты подтверждают техническое поведение интерфейса, но не доказывают, что выбранные пять приоритетов оптимальны для всех пользователей. Следующим доказательным шагом остаются наблюдаемые тесты с реальными пользователями и анализ реальных поисковых запросов.
