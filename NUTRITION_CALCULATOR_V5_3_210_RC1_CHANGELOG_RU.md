# Changelog v5.3.210-rc1

## Основа релиза

RC1 основан на `v5.3.210-pc2`. Продуктовая логика PC2, нормативы P1.2, provenance P1.3 и formula registry P1.4 сохранены.

## Добавлено

- панель «Beta-диагностика и обратная связь»;
- проверка версии runtime и режима совместимости;
- проверка загрузки продуктовой базы и ошибок ресурсов;
- проверка API health без выполнения AI-запроса;
- скачивание privacy-safe диагностического JSON;
- копирование краткой технической сводки;
- инструкция, какие сведения приложить к сообщению об ошибке;
- `robots.txt` с полным запретом индексации beta;
- защитный `X-Robots-Tag` для всех ответов;
- `Cross-Origin-Resource-Policy` и запрет cross-domain policy;
- immutable cache для версионированных assets/data;
- сжатие текстовых ресурсов;
- remote smoke tool;
- RC1 unit и Chromium-сценарии;
- Product Validation Sprint внутри полного проекта.

## Исправлено

- cache-key CSS runtime-manifest приведён к `v5.3.210-rc1`;
- правило immutable cache работает при публикации как в корне, так и в подпапке сайта;
- диагностический модуль не зависит от `Promise.prototype.finally`, что улучшает совместимость legacy-ветки;
- унаследованные PC1/PC2-тесты теперь различают продуктовую основу PC2 и оболочку релиза RC1;
- исходный CSS диагностического модуля не включается в HOSTING отдельно от итогового bundle;
- кнопка «Рассчитать» недоступна до официального события `app:ready`, поэтому первый разрешённый тап не теряется во время параллельной загрузки runtime;
- отложенный возрастной профиль фиксируется сразу после перехода к следующему полю: мобильная форма больше не меняет высоту непосредственно во время нажатия «Рассчитать»;
- browser- и DOM-регрессии используют тот же readiness-контракт, что и production-загрузчик;
- регрессия поиска учитывает объединённые карточки способов приготовления и проверяет наличие нужного варианта внутри канонического семейства продукта.

## Не изменено

- 29 зарегистрированных формул;
- 113 independent golden cases;
- нормативные значения;
- числовые значения продуктов;
- protected modes;
- правило подтверждения полного дня;
- ограничение пяти главных приоритетов;
- статус `EXTERNAL_VALIDATION_PENDING`.
