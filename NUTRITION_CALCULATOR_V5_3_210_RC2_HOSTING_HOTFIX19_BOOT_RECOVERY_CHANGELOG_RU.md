# HOTFIX19 — восстановление запуска runtime

## Причина

В HOTFIX18 и производном hosting-кандидате 5Б.0 был нарушен внутренний контракт версий стартовой цепочки:

- runtime-manifest объявлял `v5.3.210-rc2-hf18`;
- modern- и legacy-bootstrap ожидали `v5.3.210-rc2`;
- runtime-selector и bootstrap продолжали использовать cache-busting HOTFIX1.

При свежем запуске bootstrap останавливался до загрузки базы продуктов и рабочих модулей. Защитный экран «Не удалось загрузить файлы калькулятора» срабатывал правильно, но его общий заголовок мог создать впечатление неполной загрузки файлов.

## Изменения

1. Введён единый релизный идентификатор `v5.3.210-rc2-hf19` для index, runtime-manifest, selector и обоих bootstrap.
2. Добавлен трёхсторонний handshake:
   - ожидаемая версия из index;
   - версия bootstrap;
   - версия runtime-manifest.
3. При рассогласовании технические сведения теперь показывают все три значения.
4. После успешной загрузки `__APP_BOOTSTRAP_META__.status` получает значение `ready`; при фатальной ошибке — `fatal`.
5. Query-параметры selector, modern-bootstrap, legacy-bootstrap и compatibility gate обновлены до HF19, чтобы обойти immutable-кэш старой сборки.
6. Hosting-self-test переведён на новый runtime-manifest.
7. Расчёты, нормативы, продуктовая база, HEI, коррекция, отчёт и UI-модули не изменялись.
