# P2.0B — повторный аналитический аудит

## Проверяемый вопрос

Может ли инфраструктура P2 создать ложное впечатление завершённой внешней валидации либо принять формально заполненный, но недоказательный evidence-файл?

## Выявленные слабые места первого прохода

1. Первоначальный evidence validator доверял агрегированному `decision: ACCEPTED` и заявленным метрикам.
2. Пустой шаблон рецензента требовал вручную переносить 51 ID, что создавало риск пропусков.
3. Static gate ошибочно ожидал версию P2.0 внутри неизменённых P1.5-артефактов.
4. Новый browser-тест использовал несовместимую fixture и мог давать инфраструктурный FAIL.
5. Несколько browser-сценариев в одном P2-файле завершались нестабильно в локальном Playwright-процессе.
6. Формулировка запрета clinical claim требовала отдельной проверки на ложноположительное распознавание отрицательных утверждений.

## Исправления

- evidence gate теперь пересчитывает результаты из первичных reviewer/pilot records;
- проверяются version binding, парные SHA-256, независимость, профессиональная область и подпись;
- каждый рецензент обязан вернуть 51 уникальный case response;
- критические safety-кейсы требуют единогласного принятия;
- пилотные completion rate и critical use errors пересчитываются, а не принимаются на доверии;
- reviewer template заранее содержит все 51 ID со статусом `NOT_REVIEWED` и не раскрывает ответы;
- добавлена слепая CSV-матрица;
- версии унаследованных P1.2–P1.5-слоёв проверяются отдельно от версии текущего релиза;
- P2 browser gate объединён в один атомарный сценарий и проверяет DOM, видимость, runtime audit и итоговый отчёт;
- synthetic accepted fixture явно маркирован как test-only и нигде не сохраняется как evidence продукта.

## Результат второго прохода

- слепой пакет не содержит expected, formula ID, reference или severity;
- парные хэши JSON-пакета и приватного ключа воспроизводятся;
- pending evidence корректно отклоняется;
- корректная тестовая структура принимается;
- отсутствие подписи, неполный review, несогласие по critical case, critical pilot error и version mismatch блокируют gate;
- активные пользовательские поверхности не содержат разрешённого положительного clinical claim;
- нерешённых findings P2.0B не осталось.
