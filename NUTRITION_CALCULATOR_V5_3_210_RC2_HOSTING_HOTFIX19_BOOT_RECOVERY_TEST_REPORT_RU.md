# Отчёт о тестировании HOTFIX19 Boot Recovery

## Воспроизведение дефекта

Исходный hosting-кандидат HF18/5Б.0 воспроизведён в чистом Chromium через полнофункциональный ресурсный адаптер. Результат:

- runtime-manifest: `v5.3.210-rc2-hf18`;
- защитное окно: показано;
- техническая причина: «Манифест модулей отсутствует или не соответствует версии релиза»;
- основной bootstrap не перешёл к загрузке продуктов и runtime.

Доказательство: `reports/hf18-boot-failure-reproduction.json`.

## Проверка исправления

HOTFIX19 проверен на ширинах 390 × 844 и 1440 × 900.

В обоих случаях:

- manifest, selector, ожидаемая версия и bootstrap согласованы как `v5.3.210-rc2-hf19`;
- статус bootstrap — `ready`;
- база продуктов загружена;
- загружено 76 runtime-скриптов;
- неудачно загруженных runtime-скриптов — 0;
- защитное окно отсутствует;
- загрузочный overlay штатно закрывается;
- навигационная оболочка и поиск присутствуют;
- горизонтального переполнения нет;
- ошибок console/pageerror нет.

Время полного запуска в локальном адаптере: около 1,5–1,7 секунды; с ожиданием закрытия overlay — менее 5 секунд.

## Статическая и регрессионная проверка

- 36 проверок загрузочного контракта — PASS;
- modern-bootstrap — корректный JavaScript;
- legacy-bootstrap — корректный JavaScript;
- selector и compatibility gate — корректный JavaScript;
- runtime closure — 277 из 277 файлов;
- единственный активный manifest — HF19;
- нормативный реестр, формульный реестр, provenance и 12 продуктовых JSON-фрагментов побайтово совпадают с HF18/5Б.0;
- изменены только стартовые файлы и index; 269 остальных runtime-файлов побайтово неизменны.

## Ограничение среды

Прямой переход Chromium к локальному HTTP-адресу блокируется административной политикой среды. Поэтому браузерная проверка проведена через тот же полнофункциональный route-адаптер, который отдаёт реальные файлы сборки и сохраняет порядок динамической загрузки. Окончательная проверка домена выполняется после загрузки архива на hosting.
