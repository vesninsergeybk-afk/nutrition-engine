# HOTFIX13 UNIFIED REPORT — список изменений

## Назначение релиза

HOTFIX13 выполняет этап 4 генерального плана перестройки интерфейса: создаёт единый сериализуемый снимок отчёта и переводит рабочий экран «Отчёт», печать и сохранение в PDF на один содержательный шаблон.

Релиз не меняет расчётные формулы, нормы, продуктовую базу, HEI или правила коррекции. Он собирает уже рассчитанные данные и показывает их в разных форматах без повторного вычисления.

## Основные изменения

### 1. Единая модель отчёта

Добавлен объект `nutrition-workspace-report-v1`, включающий:

- профиль человека;
- рассчитанные потребности;
- состав рациона;
- энергию и основные показатели;
- нутриенты и применимые ориентиры;
- HEI и отдельные ограничения;
- краткую оценку рациона;
- качество исходных данных;
- подтверждённые изменения текущего сеанса;
- параметры состава отчёта;
- служебные метаданные расчётного снимка.

Модель пригодна для сериализации в JSON. Компонент отчёта не пересчитывает нутриенты и HEI собственными формулами: используются `NutritionReportV5` и `NutritionAnalysisWorkspaceHF7`.

### 2. Самостоятельный рабочий экран «Отчёт»

Маршрут `#report` теперь открывает `workspaceReportPanel`, а не набор старых DOM-секций длинного полотна.

На экране доступны:

- просмотр отчёта;
- печать;
- сохранение в PDF через системный диалог печати;
- выгрузка сериализованного снимка в JSON;
- ограниченный набор параметров состава.

Длинное полотно сохранено как резервный режим миграции.

### 3. Один шаблон для экрана, печати и PDF

Функция `buildBodyHtml()` формирует содержательную часть документа. Тот же результат используется:

- в рабочем предпросмотре;
- в печатном документе;
- при сохранении в PDF.

Различается только внешнее оформление. Отдельного текста или повторного расчёта для PDF нет.

### 4. Параметры состава без конструктора документов

Пользователь может включать и исключать только пять дополнительных частей:

1. подробную таблицу нутриентов;
2. полный разбор компонентов HEI;
3. продукты-вкладчики;
4. применённые изменения;
5. методику и ограничения.

Профиль, потребности, рацион, основные итоги, качество данных и краткий HEI остаются обязательными.

### 5. Отдельные ограничения рядом с HEI

Общий балл HEI больше не заслоняет:

- подтверждённые превышения применимых верхних уровней;
- превышения рекомендуемых ограничений;
- показатели, которые невозможно надёжно оценить.

Если рабочая модель анализа временно недоступна, ограничения восстанавливаются из канонического `dietAssessment`.

### 6. Читаемый язык отчёта

Технические обозначения `cup-eq` и `oz-eq` не выводятся пользователю. Они заменяются нейтральным русским обозначением условной пищевой порции.

Для применённых замен используются названия продуктов, а не внутренние ключи. Показываются количества до и после изменения.

### 7. Мобильный предпросмотр

На узком экране широкие таблицы заменяются карточками. Постоянная нижняя навигация остаётся единственной закреплённой областью. У отчёта предусмотрен безопасный нижний отступ.

### 8. Доступность и устойчивость управления

- параметры состава не пересоздаются после каждого переключения;
- клавиатурный фокус остаётся на выбранном флажке;
- предпросмотр получает состояние `aria-busy` на время обновления;
- неактивные старые блоки отчёта исключены из рабочего маршрута;
- старые кнопки печати и PDF перенаправлены на новый единый отчёт.

## Обновлённые файлы

Обновлены навигационная оболочка, runtime-конфигурация, CSS-bundle, runtime-manifest, hosting self-check, release gate, сборщик и верификатор архивов, проверки версий и регрессионные тесты.

## Что намеренно не добавлено

- редактор макета отчёта;
- несколько дизайнерских шаблонов;
- облачное хранение документов;
- отдельный серверный генератор PDF;
- новая расчётная модель;
- долговременная история всех коррекций;
- удаление резервного длинного полотна.

Эти функции не требуются для выполнения этапа 4 и увеличили бы риск расхождения данных.
