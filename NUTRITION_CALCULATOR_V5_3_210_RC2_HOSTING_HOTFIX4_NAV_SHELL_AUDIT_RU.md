# HOTFIX4 NAV SHELL — итоговый архитектурный и UX-аудит

## Принятое решение

Новая информационная архитектура внедрена как безопасный параллельный слой. Это снижает основной риск проекта: расчётные блоки не переписаны, не дублированы и не перенесены в отдельную вторую реализацию.

## Почему решение устойчиво

1. **Один источник данных.** Оболочка показывает существующие секции; расчётные модели и события остаются общими.
2. **Обратимость.** Пользователь может вернуться к полному полотну без перезагрузки и потери состояния.
3. **Постепенная миграция.** Содержимое разделов можно улучшать независимо после проверки навигации на реальной эксплуатации.
4. **Разные устройства — одна смысловая структура.** На desktop меняется только форма навигации, а не названия и логика разделов.
5. **Отчёт остаётся длинным.** Последовательное полотно сохранено там, где оно действительно полезно: просмотр, печать и PDF.

## Что намеренно не сделано

- не создан второй набор расчётных компонентов;
- не введены шесть верхнеуровневых вкладок по прежним «шагам»;
- не добавлен переключатель между двумя независимыми приложениями;
- не перенесены сразу все настройки и карточки;
- не изменены формулы, базы и контракты HEI.

## UX-вердикт

Оболочка улучшает повторное использование калькулятора: пользователь может быстро переходить по циклу «Рацион → Анализ → Улучшить → Отчёт», не прокручивая всё приложение. При этом для первичного ознакомления и аварийного возврата остаётся прежнее длинное полотно.

Интерфейс не получил лишнего постоянного слоя управления:

- desktop — компактная боковая панель;
- mobile — одна нижняя панель;
- настройки раскрываются только по запросу;
- внутренние представления показываются только в разделе анализа;
- служебные и методические блоки не дублируются между рабочими областями.

## Готовность следующего этапа

После периода параллельной эксплуатации можно переходить к поэкранной оптимизации:

- упростить содержимое «Рациона»;
- собрать действительно краткий «Обзор»;
- развить связку «показатель → вкладчики → сценарий → применить» в разделе «Улучшить»;
- перевести отчёт на единый объект модели вместо зависимости от порядка DOM.

Сейчас безопасный следующий шаг выполнен полностью: навигационная архитектура уже работает на реальном коде, но не ставит под угрозу проверенную функциональность.
