# P1.5B — повторный аналитический аудит UX

Версия: `v5.3.210-p1.5`

## Что было проверено повторно

Анализ проводился не по макетам, а по реально работающему P1.5 runtime в Chromium. Проверялись три состояния:

1. пустой калькулятор;
2. рассчитанные потребности без продуктов;
3. рацион с первым добавленным продуктом.

## Исходная проблема

До P1.5 пустая страница имела приблизительную высоту:

- desktop 1440×1000 — **7030 px**;
- mobile 390×844 — **8235 px**.

Пользователь одновременно видел ввод профиля, поиск, AI-импорт, пустые результаты, HEI, расширенную методику, панели качества данных и AI-планировщик. Формально всё было доступно, но приоритет действий не читался.

## Результат основного прохода P1.5A

После введения четырёх этапов и первичного прогрессивного раскрытия пустой экран сократился до:

- desktop — **3214 px** (примерно −54,3%);
- mobile — **3194 px** (примерно −61,2%).

## Finding второго прохода

Первый редизайн решал пустое состояние, но после добавления продукта страница снова разрасталась приблизительно до **11 236 px**. Причина была не в самом рационе, а в одновременном раскрытии:

- полной таблицы итогов;
- HEI-панели;
- детальных микронутриентов;
- полного набора рекомендаций HEI;
- поисковой выдачи;
- формы потребностей;
- расширенных аналитических блоков.

Таким образом, перегрузка была перенесена с первого экрана на первый результат, а не устранена полностью.

## Исправления P1.5B

- введён краткий result overview;
- полные totals и HEI объединены в закрытый по умолчанию drawer «Основной итог рациона»;
- HEI-рекомендации получили отдельный вложенный уровень раскрытия;
- поисковая выдача после добавления продукта сворачивается;
- форма потребностей после успешного расчёта не занимает основную вертикаль;
- расширенная методика и AI остаются доступными, но не конкурируют с первым итогом.

После этих изменений рабочее состояние с первым продуктом сократилось приблизительно до **4578 px** до осознанного раскрытия полной аналитики — примерно на **59,3%** относительно промежуточного состояния.

## Проверка на ложное упрощение

Контролы не удалены из DOM, обработчики расчётов не заменены, данные не урезаны. Изменена только иерархия предъявления:

- обязательное — видно сразу;
- зависимое от данных — появляется после данных;
- профессиональное и вспомогательное — открывается по запросу;
- печать раскрывает содержимое полностью.

## Вывод

P1.5B подтвердил, что качественное упрощение определяется не минимальным числом элементов, а соответствием количества видимой информации текущему решению пользователя.
