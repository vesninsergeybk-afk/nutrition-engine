# HOTFIX4 NAV SHELL — список изменений

## Назначение

В сборку добавлена параллельная навигационная оболочка поверх действующего калькулятора. Она не заменяет и не копирует расчётные модули: существующие секции остаются в DOM, сохраняют идентификаторы, состояние и обработчики, а оболочка только управляет их видимостью и навигацией.

По умолчанию открывается прежнее длинное полотно. Новый режим включается пользователем через переключатель **«Полотно / Разделы»**. Это позволяет проверить новую информационную архитектуру на реальном приложении без рискованной одномоментной миграции.

## Новая структура

Основные рабочие области:

- **Рацион** — потребности, быстрый поиск, альтернативный ввод, текущий рацион и дополнительные инструменты;
- **Анализ** — локальные представления «Обзор», «Нутриенты» и «HEI»;
- **Улучшить** — приоритетные отклонения, рекомендации и ИИ-помощник по перестройке;
- **Отчёт** — последовательная сводка, печать и PDF.

На широком экране используется боковая навигационная панель. На мобильном — одна нижняя панель из четырёх пунктов; прежняя плавающая мини-корзина в режиме разделов скрывается, поэтому двухэтажной нижней панели нет.

## Реализовано в коде

- hash-маршруты: `#ration`, `#analysis/overview`, `#analysis/nutrients`, `#analysis/hei`, `#correction`, `#report`;
- корректная работа кнопок браузера «Назад» и «Вперёд»;
- сохранение последнего рабочего раздела;
- отдельное положение прокрутки для каждого маршрута;
- мгновенное позиционирование при смене режима и раздела без затяжной плавной прокрутки;
- сохранение введённых значений и рациона при любых переходах;
- прямые переходы из существующих ссылок к соответствующим разделам;
- повторный вызов `resize` после активации скрытого раздела для корректной отрисовки графиков;
- прогрессивное раскрытие профиля и настроек;
- возможность в один клик вернуться к полному длинному полотну;
- публичный API `window.NavigationShellV1` и события жизненного цикла оболочки.

## Защита совместимости

- длинное полотно остаётся режимом по умолчанию;
- исходные секции не клонируются и не пересоздаются;
- старые ID, события и расчётные контракты сохранены;
- modern- и legacy-контуры содержат одинаковый контроллер;
- недоступность `localStorage` или `sessionStorage` не останавливает загрузку;
- вспомогательный импорт по фото/аудио показывается только в разделе «Рацион»;
- служебная диагностика не засоряет рабочие разделы;
- печать скрывает навигационную оболочку и сохраняет прежнее представление документа.

## UX-доработки по итогам браузерного аудита

- исправлено появление навигации в режиме длинного полотна;
- убрано дублирование подробной таблицы HEI в разделе коррекции;
- устранён лишний блок импорта в разделах анализа;
- убран псевдозаголовок «Шаг 1» из рабочего режима;
- локальные представления анализа получили различимое активное состояние;
- второстепенные кнопки боковой панели перестали конкурировать с основными действиями;
- компактная сводка рациона стала визуально спокойнее и контрастнее;
- исправлено перекрытие текста кнопкой настроек на узком экране;
- устранено горизонтальное переполнение на ширине 390 пикселей;
- исправлен контраст подписи боковой панели по результатам axe-аудита.

## Граница текущего этапа

Это навигационная оболочка в параллельном режиме, а не окончательная глубокая переработка всех карточек. На следующем этапе можно постепенно оптимизировать содержимое каждого раздела, уже не затрагивая расчётное ядро и не поддерживая две независимые версии приложения.
