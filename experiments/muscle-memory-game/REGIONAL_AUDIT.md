# Аудит региональных препаратов и послойной анатомии

Дата контрольной точки: 2026-09-25.

## Контур 1. Анатомическая семантика

Проверено:
- анатомический слой отделён от геометрической видимости из камеры;
- глубокая мышца, уже открытая в анатомическом окне, не снимается вместе с поверхностным слоем;
- локальная подсказка «Глубже здесь» использует только мышечные учебные цели;
- без курированного depth profile луч камеры не используется как доказательство анатомической глубины;
- рабочие depth profiles отделены от статуса геометрии `verified_for_teaching`.

Исправлено:
- убрана зависимость анатомического снятия слоя от camera-visible peeling;
- выровнены межисточниковые regex для ладонных межкостных, мышц, поднимающих рёбра, и подзатылочных прямых мышц.

## Контур 2. Состояние и пользовательские переходы

Проверены последовательности:
- выбор мышцы → «Глубже здесь» → изоляция → возврат окружения;
- повторный клик по уже изолированной мышце;
- смена виртуального препарата;
- переключение Z-Anatomy / BodyParts3D;
- переход Атлас ↔ Тренировка.

Исправлено:
- повторный клик больше не рассинхронизирует флаг `isolated` и фактическую сцену;
- при смене модели очищаются устаревшие кнопки «Глубже здесь» со старыми sid;
- при смене препарата очищаются выбранные структуры, подсветка и deep-focus state.

## Контур 3. Межисточниковая согласованность

Добавлен `check-virtual-specimen-coverage.mjs` для всех 29 препаратов.

Проверяется:
- препарат не пуст в каждом источнике;
- scene targets не меньше question targets;
- общий мышечный концепт не может относиться к препарату только в одном источнике;
- различия детализации источников разрешены и логируются отдельно.

Результат контрольной проверки:
- semantic mismatches: 0;
- ротаторная манжета: 4/4 в обоих источниках;
- плечевой пояс: 13/13;
- hamstrings: 3/3;
- quadriceps: 4/4;
- подзатылочный комплекс: 4/4.

Известное ограничение:
- текущий BodyParts3D неполон для переднебоковой брюшной стенки: 1 учебная цель против 5 у Z-Anatomy.

Для этого введён `specimenDepthAvailability()`: неполный источник получает `source-incomplete` и не может включить полноценную анатомическую послойность.

## Контур 4. Пространственная сцена и производительность

Исправлено:
- камера и костное окно рассчитываются по question targets, а не по длинным cover/context muscles;
- покровные мышцы остаются видимым анатомическим контекстом, но не растягивают фокус препарата;
- поиск внутри региона использует один Set sid вместо повторного пересчёта activeRegionStructureIds для каждой структуры;
- тканевые структуры используют один вычисленный набор активных концептов;
- при смене препарата сцена больше не перестраивается дважды.

Добавлен костный аудит обоих источников.

Уточнены тазовые ориентиры:
- BodyParts3D использует `Right/Left hip bone`, поэтому в словарь добавлены `hip bone|os cox`;
- тазовая кость теперь учитывается в препаратах ягодичной области, бедра, hamstrings, quadriceps, adductors, hip-flexors и связанных препаратах.

## Контур 5. Браузерный пользовательский путь

Полный браузерный smoke запускается только на контрольной точке, а не после каждого коммита.

В checkpoint-проход дополнительно включено:
- Z-Anatomy: живот = 5 целей, depth capability = `ok`;
- BodyParts3D: живот = 1 цель, depth capability = `source-incomplete`;
- попытка снять анатомический слой на неполном источнике должна показать понятное объяснение, а не ложный слой.

## Открытые ограничения после аудита

1. Геометрическая валидация плечевого региона остаётся незавершённой: `verified_for_teaching = 0/19`.
2. Курированные depth profiles пока есть не для всех регионов.
3. Покровные context muscles пока показываются целыми mesh; настоящее геометрическое отсечение длинной мышцы по границе виртуального препарата ещё не реализовано.
4. Источники различаются по гранулярности, особенно в стопе и мелких сегментарных мышцах.
5. BodyParts3D не должен использоваться как полный источник послойности брюшной стенки в текущей закреплённой версии.

Следующий большой функциональный этап после закрытия этого checkpoint — motion proof-of-concept, начиная с локтя/бицепса, но только после зелёного полного браузерного прохода.


## Дополнение после разрушительного прохода

### Deep links: мышца, а не mesh

Дополнительная проверка показала, что одна учебная мышца может состоять из нескольких mesh-компонентов одной стороны. Поэтому ссылка «Глубже здесь» теперь:
- дедуплицируется по паре `мышечная цель × сторона`;
- при выборе показывает все компоненты выбранной мышцы этой стороны;
- не выдаёт одну головку или часть mesh за всю мышцу.

### Кости кисти и стопы

Первоначальный общий шаблон `phalan` формально допускал фаланги стопы в сырой список костных кандидатов кисти. Пространственное окно отсеивало их в runtime, но словарь был неточен. Шаблоны кисти и стопы разделены, а костный аудит теперь запрещает foot/toe anchors в препарате кисти.

### Ограничение длительности CI

Обычные commits продолжают выполнять fast-CI. Полный Chromium-smoke запускается только checkpoint-коммитом с `[full-smoke]`.

Hard timeout полного workflow уменьшен с 25 до 15 минут. Нормальный длительный прогон может занимать несколько минут из-за Chromium и двух удалённых 3D-источников, но зависший job не должен удерживаться почти полчаса.

## Выявленные продуктовые долги, которые не следует маскировать

### 1. Настоящий пространственный срез препарата

Сейчас question targets задают камеру и региональное окно, а context covers не расширяют framing. Однако мышцы и отдельные кости внутри окна всё ещё включаются как целые mesh-объекты.

Следующий уровень виртуального препарата — пространственно ограничивать геометрию за пределами регионального окна, например:
- показывать релевантный участок плечевой кости вместо визуального доминирования всей кости;
- ограничивать грудной костный контекст плечевого пояса;
- показывать регионально релевантную часть широчайшей или большой грудной мышцы как покров, не превращая препарат снова в почти целое туловище.

Это отдельная инженерная задача: простого скрытия объектов недостаточно, потребуется clipping/cropping или заранее подготовленные региональные mesh.

### 2. Расширение библиотеки препаратов

Текущие 29 препаратов покрывают основные учебные зоны, но ещё не исчерпывают все практически значимые регионы. Следующие кандидаты:
- лицо и жевательный комплекс;
- специализированный препарат мышц тазового дна.

Их следует добавлять только после проверки состава мышц, костных ориентиров и пригодности обоих 3D-источников, а не как формальные фильтры каталога.

### 3. Полнота depth profile

Текущий source-capability guard использует минимальное число обязательных учебных целей и затем проверяет наличие depth-описания у видимых целей. Для закреплённых источников этого достаточно и он уже выявил неполный BodyParts3D-живот.

Для будущих источников более устойчивой схемой будет manifest конкретных обязательных мышечных концептов для каждого depth profile, а не только числовой минимум.
