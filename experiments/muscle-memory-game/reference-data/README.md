# Muscle reference data

Эта папка — независимый слой справочных данных для анатомического тренажёра.

## Граница ветки

Ветка `feature/muscle-reference-data` не меняет текущий интерфейс тренажёра и не должна править:
- `app.js`;
- `index.html`;
- стили интерфейса;
- 3D-загрузчики;
- существующий `muscle-reference-data.js`.

До завершения параллельной работы над интерфейсом здесь добавляются только:
- проверенные анатомические данные;
- связи «мышца — область — слой — ориентиры»;
- указатели на иллюстрации;
- сведения об источниках и статусе проверки;
- автоматические проверки целостности данных.

Интеграция в основной интерфейс выполняется отдельным проходом после стабилизации рабочей ветки тренажёра.

## Принцип наполнения

Справочник не копирует учебник дословно. Из источников извлекаются факты, затем они нормализуются и сверяются.

Для каждой мышцы достаточно хранить сведения, которые помогают:
1. узнать структуру;
2. понять её положение и слой;
3. связать мышцу с костными ориентирами;
4. понять направление волокон и основные движения;
5. увидеть отношения с соседними структурами;
6. подобрать корректную иллюстрацию.

Иннервация и кровоснабжение допускаются как расширенные поля, но не обязаны перегружать основную учебную карточку.

## Проверка источников

Основной учебный источник на первом проходе — «Миология» ИГМА (2018). Он очень содержателен, но не принимается как безошибочный источник. Спорные места сверяются с академическими атласами и современными анатомическими источниками.

Материалы курса (анатомические карты модулей 5–7) задают педагогический объём: слои, крупные ориентиры, функции через движение, отсутствие ложной точности при пальпации глубоких структур.

Материалы, содержащие диагностические или лечебные утверждения, не используются как источник анатомических фактов без отдельной проверки.

## Иллюстрации и права

Наличие изображения в библиотеке не означает разрешения на его публичное встраивание.

Для каждого изображения хранится `rightsStatus`:
- `public-domain` — можно включать после проверки конкретного файла;
- `owned` — собственный материал проекта;
- `licensed` — есть подходящая лицензия;
- `review` — разрешение на публичное использование не подтверждено;
- `generated` — изображение создано специально для проекта и прошло анатомическую проверку.

Файл со статусом `review` не получает публичный `src`. Валидатор контролирует это правило.

## Текущий пилот

Первый набор выбран по реальным пробелам тренажёра:
- широчайшая мышца спины;
- передняя зубчатая мышца;
- наружная косая мышца живота;
- жевательная мышца.

После проверки схемы каталог расширяется по регионам, а не случайным списком мышц.


## Представление карточки

Сырые технические поля `kind` и `layer` предназначены для логики данных и 3D-сопоставления. Их нельзя выводить ученику напрямую.

Для пользовательской карточки используется `presentation.js`. Рекомендуемый порядок чтения:
1. название на русском и латыни, область, тип структуры и понятная отметка глубины;
2. основные действия;
3. начало и прикрепление;
4. направление волокон;
5. костные и поверхностные ориентиры;
6. отношения с соседними структурами;
7. иннервация;
8. «Ориентир для изучения»;
9. источники и статус проверки.

Поле `movementCueRu` в данных исторически содержит не только описание движения, но и методический ориентир по слою, вариабельности или ограничениям пальпации. Поэтому в интерфейсе оно должно называться «Ориентир для изучения», а не «Движение» или «Тест».

Для вариабельных, спорных структур и частей мышц интерфейс должен показывать явный бейдж. Не следует скрывать неопределённость за уверенной формулировкой.

## Редакционные правила русскоязычной карточки

Основной текст карточки пишется по-русски. Латинское название хранится отдельно в `names.latin` и не должно многократно повторяться внутри русских пояснений без необходимости.

Сокращения суставов и англоязычные рабочие обозначения (`MCP`, `MTP`, `FDL`, `mesh` и т. п.) не выводятся ученику без расшифровки. Технические имена BodyParts3D хранятся в `modelAliases` и `model-aliases.js`.

Формулировки должны различать:
- установленный анатомический факт;
- вариабельность;
- традиционное описание, которое оспаривается современными данными;
- учебное упрощение.

Если структура глубокая и не может быть надёжно изолирована с поверхности, карточка объясняет её слой и отношения, а не создаёт искусственную «пальпаторную задачу».


## Иерархия иллюстраций

Для карточки мышцы используется двухуровневая система.

1. Основная иллюстрация строится непосредственно из геометрии выбранной структуры в активной 3D-модели. На ней отображается именно выбранная мышца или выбранная именованная часть мышцы; ближайшие кости служат пространственными ориентирами. Региональная пластина не может заменять эту иллюстрацию.

2. Атласные изображения из `illustrations.js` и карточек источников являются дополнительными. Они размещаются только в свёрнутом разделе источников и должны быть подписаны как региональная, слоевая или локальная пластина. Наличие мышцы на общей пластине не означает, что такая пластина является индивидуальной иллюстрацией этой мышцы.

Для сопоставлений `part` основная иллюстрация показывает выбранную часть, а текстовая карточка объясняет родительскую мышцу. Для `group` показывается выбранный элемент группы. Для `ambiguous` отображается точный 3D-объект, но подпись обязана сохранять неопределённость его анатомической идентификации.

Это правило позволяет иметь точную иллюстрацию для каждой реально выбираемой мышечной структуры без подмены локального изображения общей картой региона.


## Иерархия художественных иллюстраций и 3D

Карточка мышцы использует следующий приоритет:

1. Если есть опубликованная и точно сопоставленная художественная иллюстрация (`exact-card` или `exact-card-part`), карточка открывается на вкладке «Иллюстрация».
2. Если одновременно доступен 3D-объект, рядом показывается вкладка «3D». 3D-превью строится только после переключения на неё.
3. Если художественной иллюстрации нет, вкладка «Иллюстрация» скрыта, а карточка сразу показывает 3D.
4. Если для одной мышцы есть несколько точных рисунков, например разные брюшки или ракурсы, они листаются внутри вкладки «Иллюстрация».
5. Групповой рисунок (`group-supplement`) не считается индивидуальной иллюстрацией отдельной мышцы и не может занимать главное место в её карточке.

Реестр `source-art.js` хранит источник, страницу, нормализованную область рисунка, тип соответствия и статус прав. Анатомические подписи и функции из методичек не импортируются в справочник автоматически: текст карточки остаётся из независимо проверенной анатомической базы.

Для публичного репозитория `assetPath` разрешается только при подтверждённом статусе `public-domain`, `cc0`, `cc-by`, `cc-by-sa`, `licensed` или `owned`. Сопоставленный рисунок с `permission-unverified` остаётся `mapped-source-only` и в публичном интерфейсе автоматически заменяется 3D.
