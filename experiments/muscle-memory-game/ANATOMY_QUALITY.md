# Контроль анатомического качества

## Принцип

Высокая плотность полигонов не считается доказательством анатомической точности.

В проекте разделяются четыре уровня:

1. **геометрия** — форма и взаимное расположение структур;
2. **идентификация** — какая геометрия соответствует какой анатомической структуре;
3. **терминология** — нормативное название и допустимые синонимы;
4. **учебные утверждения** — начало, прикрепление, действие, иннервация, отношения и клинические сведения.

Каждый уровень может иметь свой источник истины.

## Целевая архитектура источников

### Контрольный целостный атлас-кандидат

**BodyParts3D 4.0 / DBCLS**

Используется как кандидат на единую систему координат, иерархию и общий набор структур. Пока не выбран как окончательная производственная геометрия.

Плюсы:
- единая система координат;
- FMA-связи и иерархия;
- полный целостный человек;
- актуальная официальная лицензия DBCLS CC BY 4.0.

Ограничения:
- сами авторы BodyParts3D предупреждают, что в данных могут быть ошибки для анатомического образования;
- официальный bulk-download 4.0 содержит mesh с заявленным polygon reduction rate 99%;\n- используемая в Quality Lab конверсия Human Atlas затем дополнительно упрощает каждый named mesh примерно до 22% исходных индексов с ограничением относительной ошибки 0,2%; поэтому Quality Lab нельзя считать проверкой максимальной поверхностной детализации;
- данные представляют одного взрослого мужчину, а не анатомическую вариативность.

### Региональная экспертная сверка

**Open Anatomical 3D Model / AnatomyTOOL**

Проект 2022–2024 создавался кафедрами анатомии UMC Utrecht, Maastricht University, Leiden University Medical Center и KU Leuven для анатомической коррекции открытой 3D-модели и использования её в образовании.

Для плечевого модуля в AnatomyTOOL есть отдельный Open3DModel ротаторной манжеты и связанные региональные материалы.

Использование:
- проверка формы;
- проверка пространственных отношений;
- проверка того, какие структуры должны быть представлены отдельно;
- региональная замена геометрии только после проверки совместимости координат и лицензии.

### Контроль по данным реального тела

**Visible Human Project / NIH 3D** и **Open Anatomy Project**

Использование:
- не как универсальная «идеальная» геометрия;
- как независимый контроль сегментации и пространственных отношений;
- особенно полезно для конкретных регионов, где есть MRI/CT/cryo-derived atlas.

Visible Human исходные cross-sectional datasets находятся в public domain. Конкретные производные модели NIH 3D нужно проверять по лицензии каждой записи.

Open Anatomy содержит MRI/CT-derived региональные атласы.

### Терминология

**FIPAT Terminologia Anatomica, 2nd edition (TA2)**

Использование:
- нормативные латинские названия;
- стандартная структура терминов;
- фиксация синонимов отдельно от основного названия.

Индивидуальные термины TA2 находятся в public domain; сам PDF распространяется CC BY-ND 4.0.

## Почему модели нельзя просто наложить друг на друга

Разные источники могут представлять разных людей, иметь разный рост, положение конечностей, сегментацию, систему координат и степень художественной реконструкции.

Поэтому прямое «смешивание» вершин разных атласов может создать анатомически невозможные переходы.

Допустимое объединение:
- один источник задаёт основную систему координат;
- другой используется для независимой проверки;
- локальная геометрия заменяется только после регистрации, проверки ориентиров и ручного контроля;
- происхождение каждой заменённой структуры сохраняется в manifest.

## Критерий допуска структуры в учебный режим

Структура получает статус `verified_for_teaching` только если:

- название сверено с TA2/FMA;
- геометрия распознаваема и не содержит очевидных топологических дефектов;
- начало и прикрепление находятся на анатомически допустимых областях;
- отношения с соседними костями и мышцами согласуются с независимым источником;
- правая/левая сторона не перепутаны;
- упрощение mesh не уничтожает значимые ориентиры;
- указана лицензия и происхождение.

До этого интерфейс должен трактовать модель как экспериментальную.

## Текущий плечевой Quality Lab

`quality-lab.html` загружает каталог и выбранные структуры плечевого региона из browser-ready BodyParts3D 4.0 pipeline проекта `ashemag/human-atlas`. Это контрольная web-модель для проверки структуры данных и пространственной согласованности, а не high-resolution эталон.

Цель страницы — сравнение и аудит. Она не заменяет основной тренажёр автоматически.


## Кандидат максимальной геометрической детализации: BodyParts3D/Anatomography 4.3 full-resolution

Репозиторий `olivercase/body_parts_3d_api` предоставляет проверяемый manifest из 3 210 mesh-компонентов версии 4.3 и downloader к внутренним endpoint Anatomography.

Для плечевого региона manifest показывает, среди прочего:

- дельтовидную как три отдельных компонента: clavicular / acromial / spinal;
- трапециевидную как descending / transverse / ascending;
- большую грудную как clavicular / sternocostal / abdominal;
- biceps brachii как long / short head;
- triceps brachii как long / lateral / medial head;
- отдельные supraspinatus, infraspinatus, subscapularis, teres minor, teres major;
- отдельные levator scapulae, rhomboid major/minor, serratus anterior, coracobrachialis;
- отдельные scapula, clavicle и humerus.

Это существенно полезнее для функциональной анатомии, чем единый объект мышцы.

Однако источник 4.3 не является официальным bulk-download DBCLS: геометрия извлекается через недокументированные endpoint Anatomography. Репозиторий маркирует данные старой лицензией CC BY-SA 2.1 Japan, тогда как официальный DBCLS с 2025-02-27 указывает для базы CC BY 4.0.

Поэтому статус 4.3: `candidate_high_detail_pending_provenance_and_license_review`.

До разрешения этого вопроса 4.3 можно использовать для внутреннего сравнения геометрии, но не делать зависимостью опубликованного учебного продукта.

## Текущий фактический статус проверки

На момент этого аудита ни одна из 19 структур плечевого manifest ещё не получила статус `verified_for_teaching`.

Что уже сделано:
- определены источники и критерии допуска;
- закреплены конкретные ревизии внешних web-моделей;
- создан отдельный контрольный viewer BodyParts3D 4.0;
- найден перспективный full-resolution кандидат BodyParts3D/Anatomography 4.3.

Что ещё **не** сделано:
- не проведена поструктурная сверка 19/19 по AnatomyTOOL / Visible Human;
- не подтверждены TA2-термины в manifest по каждой структуре;
- не проведена регистрация разных моделей по костным ориентирам;
- не доказано, что BodyParts3D 4.0 или 4.3 лучше Z-Anatomy для каждой конкретной мышцы;
- не утверждена окончательная лицензия/происхождение full-resolution 4.3 для публичного продукта.

До выполнения этих пунктов основная модель остаётся прототипом, а не анатомически валидированным учебным атласом.


## Дополнительные ограничения кандидата BodyParts3D/Anatomography 4.3

Проверка `MANIFEST.csv` показывает, что поле FMA ID нельзя автоматически считать точным уникальным идентификатором каждого mesh-компонента: один и тот же FMA ID встречается у нескольких разных мышц плечевого региона. Поэтому идентичность структуры должна подтверждаться по имени, иерархии BodyParts3D/FMA и независимому терминологическому источнику; FMA ID из стороннего manifest сам по себе недостаточен.

В 4.3 manifest также не обнаружен полноценный отдельный набор основных связок плечевого комплекса и сухожилий ротаторной манжеты. Следовательно, даже full-resolution 4.3 не следует называть полной моделью плечевого сустава. Для будущих сценариев на прикрепления, сухожилия, капсулу, лабрум и связки понадобится отдельный проверенный источник либо региональная модель.
