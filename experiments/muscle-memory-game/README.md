# Muscle Memory Game — MVP

Первый технический прототип игры по функциональной анатомии.

## Что уже заложено

- полноэкранная 3D-модель мышечной системы;
- вращение и масштабирование мышечной модели;
- клик по отдельной мышце;
- задания вида «Найдите надостную мышцу»;
- автоматическая проверка ответа по имени объекта;
- подсветка правильной структуры и ошибочного выбора;
- счёт правильных и ошибочных ответов;
- автоматическая проверка, какие из целевых мышц действительно присутствуют в GLB;
- диагностический режим для сверки реальных имён объектов.

## Почему это отдельная папка

Пока GitHub-подключение даёт доступ только к репозиторию `nutrition-engine` и не позволяет создать новый репозиторий. Поэтому прототип живёт в ветке `feature/muscle-memory-mvp` и папке `experiments/muscle-memory-game/`. Основная ветка калькулятора не меняется.

После проверки MVP проект лучше вынести в отдельный репозиторий.

## Запуск

Это статическое приложение. Его нужно открывать через HTTP-сервер, а не через `file://`.

Например:

```bash
python3 -m http.server 8080
```

и открыть:

```
http://localhost:8080/experiments/muscle-memory-game/
```

## Текущая модель

На первом проходе `kas.glb` загружается напрямую из открытого репозитория:

`DrMuratAltun/anatomi-simulatoru`

Это временное решение, чтобы проверить механику без ручной загрузки 8-МБ бинарного GLB через текущий коннектор GitHub.

Следующий технический шаг — положить локальную копию модели в проект и убрать внешнюю зависимость.

## Что проверяем первым

Нам нужно подтвердить три вещи:

1. реальные названия ключевых мышц в GLB совпадают с ожидаемыми шаблонами;
2. отдельная мышца уверенно выбирается касанием на телефоне;
3. сама механика «название → найти на 3D-модели» достаточно удобна, чтобы строить поверх неё дальнейшую игру.

После этого добавляем плечевой модуль:

- отведение/приведение;
- сгибание/разгибание;
- наружную/внутреннюю ротацию;
- задания «движение → мышца»;
- повторение пар мышц, которые студент путает.

## Ограничение анимации

Исходный анатомический GLB — это набор геометрических объектов, а не готовая биомеханически ригованная модель. Поэтому анатомически правдоподобное движение плеча потребует отдельной кинематической схемы: кости и связанные структуры нужно объединить в сегменты и вращать вокруг заданных осей. Мышцы при этом либо будут двигаться упрощённо вместе с сегментами, либо потребуют деформации/риггинга.

В MVP мы сначала проверяем обучение на статической 3D-анатомии, чтобы не вкладываться в сложную анимацию до проверки самой игровой механики.
