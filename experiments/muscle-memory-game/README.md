# Muscle Memory Game — MVP

Первый технический прототип игры по анатомии мышц.

## Что уже заложено

- 3D-модель мышечной системы;
- вращение и масштабирование;
- выбор отдельной мышцы касанием;
- задания вида «Найдите дельтовидную мышцу»;
- автоматическая проверка ответа по исходному имени объекта в GLB;
- подсветка правильного и ошибочного выбора;
- счёт правильных и ошибочных ответов;
- диагностика реально найденных учебных целей.

## Почему первый режим только поверхностный

При буквальном выполнении задания студент должен иметь физическую возможность нажать на нужную структуру. На полной модели глубокие мышцы могут быть закрыты поверхностными мышцами, фасциями и костями.

Поэтому первый MVP не спрашивает надостную, подлопаточную и другие структуры, которые требуют снятия слоёв. Сначала проверяем механику на доступных структурах: дельтовидной, большой грудной, широчайшей, бицепсе, трицепсе и трапециевидной.

Глубокие мышцы плечевого пояса должны появиться только после реализации режима «снять слой / изолировать область / показать глубокие структуры».

## Почему это отдельная папка

Подключение GitHub сейчас даёт доступ только к репозиторию `nutrition-engine` и не позволяет создать новый репозиторий. Поэтому прототип живёт в ветке `feature/muscle-memory-mvp` и папке `experiments/muscle-memory-game/`. Основная ветка калькулятора не меняется.

Это временное размещение. Перед дальнейшим развитием проект лучше вынести в отдельный репозиторий.

## Запуск

Приложение статическое. Его нужно открывать через HTTP-сервер, а не через `file://`.

Например:

```bash
python3 -m http.server 8080
```

и открыть:

```
http://localhost:8080/experiments/muscle-memory-game/
```

## Текущая 3D-модель

Для технического прототипа `kas.glb` загружается напрямую из:

`DrMuratAltun/anatomi-simulatoru`

Этот файл получен из Z-Anatomy / BodyParts3D и оптимизирован для браузера. В источнике указано 683 мышечных объекта, около 442 тыс. треугольников и размер около 8,1 МБ.

Важное ограничение: автор веб-конверсии прямо указывает, что исходная геометрия Z-Anatomy не является полностью проверенным анатомистами учебным эталоном; кроме того, мышечная геометрия была заметно упрощена при оптимизации. Поэтому сейчас эта модель служит **технической основой MVP**, а не утверждённым источником анатомической истины.

Перед выпуском учебного продукта выбранные структуры необходимо сверить с анатомически рецензированным источником. Open Anatomical 3D Model / AnatomyTOOL особенно интересен для такой проверки: проект 2022–2024 годов был специально направлен на анатомическую корректировку открытой модели для образования.

## Что проверяем первым

1. Загружается ли GLB стабильно в браузере и на телефоне.
2. Совпадают ли реальные имена объектов с нашими учебными сущностями.
3. Можно ли уверенно выбрать требуемую **доступную** мышцу касанием.
4. Не путается ли вращение модели с выбором ответа.
5. Имеет ли сама механика «название → найти на 3D-модели» учебную ценность.

Только после этого добавляем:

- режим снятия слоёв для глубоких структур;
- ограничение сцены нужным регионом;
- задания «движение → мышца»;
- повторение мышц, которые студент путает;
- кинематическую анимацию плечевого сустава.

## Ограничение анимации

Исходный GLB — геометрический атлас, а не готовая ригованная биомеханическая модель. Правдоподобное движение плеча потребует отдельной кинематической схемы: кости и связанные структуры нужно организовать в сегменты и задать оси вращения. Деформация мышц — отдельная задача.

Поэтому в первом MVP анимацию движения не имитируем. Сначала проверяем, работает ли сам учебный цикл.
