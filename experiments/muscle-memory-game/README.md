# Muscle Memory Game — MVP

Первый технический прототип игры по анатомии мышц.

## Что уже заложено

- 3D-модель мышечной системы;
- вращение и масштабирование;
- выбор отдельной мышцы касанием;
- задания вида «Найдите дельтовидную мышцу»;
- автоматическая проверка ответа по исходному имени объекта в GLB;
- подсветка правильного и ошибочного выбора;
- счёт правильных и ошибочных ответов;
- диагностика реально найденных учебных целей;
- отдельный полупрозрачный слой костных ориентиров, который не участвует в проверке ответа;
- быстрые ракурсы «Плечевой пояс» и «Всё тело».

## Почему первый режим только поверхностный

При буквальном выполнении задания студент должен иметь физическую возможность нажать на нужную структуру. На полной модели глубокие мышцы могут быть закрыты поверхностными мышцами, фасциями и костями.

Поэтому первый MVP не спрашивает надостную, подлопаточную и другие структуры, которые требуют снятия слоёв. Сначала проверяем механику на доступных структурах: дельтовидной, большой грудной, широчайшей, бицепсе, трицепсе и трапециевидной.

В режиме «Исследование» уже реализованы скрытие выбранной структуры, возврат последнего скрытого слоя и изоляция. В игровом режиме глубокие мышцы пока намеренно не задаются: сначала нужно проверить их геометрию и сделать выбор физически однозначным.

## Почему это отдельная папка

Подключение GitHub сейчас даёт доступ только к репозиторию `nutrition-engine` и не позволяет создать новый репозиторий. Поэтому прототип живёт в ветке `feature/muscle-memory-mvp` и папке `experiments/muscle-memory-game/`. Основная ветка калькулятора не меняется.

Это временное размещение. Перед дальнейшим развитием проект лучше вынести в отдельный репозиторий.

## Запуск

Приложение статическое. Его нужно открывать через HTTP-сервер, а не через `file://`.

Например:

```bash
python3 -m http.server 8080
```

и открыть:

```
http://localhost:8080/experiments/muscle-memory-game/
```

## Текущая 3D-модель

Для технического прототипа `kas.glb` загружается напрямую из:

`DrMuratAltun/anatomi-simulatoru`

Этот файл получен из Z-Anatomy / BodyParts3D и оптимизирован для браузера. В источнике указано 683 мышечных объекта, около 442 тыс. треугольников и размер около 8,1 МБ.

Важное ограничение: автор веб-конверсии прямо указывает, что исходная геометрия Z-Anatomy не является полностью проверенным анатомистами учебным эталоном; кроме того, мышечная геометрия была заметно упрощена при оптимизации. Поэтому сейчас эта модель служит **технической основой MVP**, а не утверждённым источником анатомической истины.

Перед выпуском учебного продукта выбранные структуры необходимо сверить с анатомически рецензированным источником. Open Anatomical 3D Model / AnatomyTOOL особенно интересен для такой проверки: проект 2022–2024 годов был специально направлен на анатомическую корректировку открытой модели для образования.

## Что проверяем первым

1. Загружается ли GLB стабильно в браузере и на телефоне.
2. Совпадают ли реальные имена объектов с нашими учебными сущностями.
3. Можно ли уверенно выбрать требуемую **доступную** мышцу касанием.
4. Не путается ли вращение модели с выбором ответа.
5. Имеет ли сама механика «название → найти на 3D-модели» учебную ценность.

Уже реализованы снятие/возврат слоёв, изоляция структуры, региональный фокус, свободная навигация и краткосрочное повышение вероятности ошибочных целей.

Следующие крупные задачи:

- провести анатомическую валидацию плечевого региона;
- после неё включить глубокие мышцы в игровой режим;
- добавить задания «движение → мышца»;
- только затем переходить к кинематической анимации плечевого сустава.

## Ограничение анимации

Исходный GLB — геометрический атлас, а не готовая ригованная биомеханическая модель. Правдоподобное движение плеча потребует отдельной кинематической схемы: кости и связанные структуры нужно организовать в сегменты и задать оси вращения. Деформация мышц — отдельная задача.

Поэтому в первом MVP анимацию движения не имитируем. Сначала проверяем, работает ли сам учебный цикл.

## Лицензионный риск

Данные Z-Anatomy распространяются по CC BY-SA 4.0. Эта лицензия разрешает коммерческое использование, но требует атрибуции и ShareAlike для адаптированного материала.

Есть существенная неопределённость именно для нашего сценария приложения. 31 августа 2026 года владелец репозитория Z-Anatomy публично ответил разработчику другого анатомического приложения, что, по его трактовке, включение модели в приложение означает необходимость распространять код приложения под той же лицензией.

Creative Commons в общем случае связывает ShareAlike с понятием адаптированного материала и отдельно отмечает, что простое объединение произведений не всегда превращает всё объединение в адаптацию. Поэтому вопрос о конкретной архитектуре приложения не стоит считать автоматически решённым в любую сторону.

Практический вывод для проекта: Z-Anatomy годится для открытого технического прототипа, но до выбора базы для закрытого коммерческого продукта нужно отдельно определить приемлемую лицензионную схему или подобрать источник с более удобной лицензией.

## Костные ориентиры

Скелет загружается отдельным GLB после мышечной модели, чтобы не задерживать появление первого экрана. Сейчас он отрисовывается как **условное рентген-просвечивание**: depth-test отключён, поэтому кости остаются видимыми поверх мышц независимо от реальной окклюзии. Этот слой нужен только для пространственной ориентации и **не участвует в raycast-проверке ответа**.

Такое отображение нельзя использовать для вывода о том, какая структура действительно лежит спереди или сзади. Для обучения топографическим отношениям нужен отдельный режим с корректной окклюзией/прозрачностью.


## Навигация

Навигация остаётся на штатном OrbitControls Three.js r185, но использует возможности, которые в первом прототипе не были включены:

- `zoomToCursor=true`: колесо приближает к точке под курсором, а не только к центру тела;
- один палец / левая кнопка — вращение;
- два пальца — одновременное приближение и перемещение;
- правая кнопка мыши — панорамирование;
- ограниченные `minDistance` и `maxDistance`, чтобы камера не проваливалась внутрь модели и не улетала бесконечно;
- «К выбранной» вычисляет bounding box уже найденной/показанной мышцы и помещает её в рабочее поле;
- «Плечевой пояс» теперь фокусирует регион через bounding box, а не через фиксированную точку камеры.

При жестах несколькими пальцами выбор ответа блокируется: pinch/pan не должен случайно засчитываться как нажатие на мышцу.

Изучены полезные открытые проекты:
- `yomotsu/camera-controls` (MIT): setOrbitPoint, fitToBox/fitToSphere, dollyToCursor, ограничения камеры;
- `ashemag/human-atlas` (MIT code + BodyParts3D 4.0 CC BY 4.0 data): мобильный anatomy viewer, isolation/focus selected structure, tap-vs-drag validation, merged geometry;
- `gkjohnson/three-mesh-bvh` (MIT): ускоренный raycast, пригодится при росте сложности сцены.

На текущем этапе дополнительную библиотеку управления камерой не добавляем: нужные базовые функции уже есть в используемом OrbitControls r185.


## Проверка целостности прототипа

Из папки `experiments/muscle-memory-game` можно запустить:

```bash
node verify.mjs
```

Проверка ловит рассинхрон HTML/JS, плавающие ссылки на upstream `main`, несогласованность audit-status в анатомическом manifest и преждевременный статус `verified_for_teaching`. Она проверяет целостность проекта, но **не заменяет анатомическую экспертизу**.
