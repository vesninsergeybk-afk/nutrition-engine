# Сравнение координатных 3D-моделей

## Вывод на текущем этапе

Одной модели, которая одновременно доказанно выигрывает по анатомической корректности, геометрической детализации, полноте структур, лицензии и скорости в браузере, пока не найдено.

Поэтому на этапе разработки применяется **модельное сравнение**, а не преждевременный выбор одного «победителя».

## Z-Anatomy — исходный Blender atlas

Роль: кандидат на детальную геометрию, совместимую с текущим прототипом.

Факты:
- открытый исходный архив `Z-Anatomy.zip` в официальном репозитории имеет размер около 86,7 МБ;
- текущий web-экспорт мышечной системы `kas.glb` — около 8,1 МБ;
- автор web-конверсии указывает, что мышечная система при экспорте была уменьшена примерно до 18% оценённого числа треугольников.

Преимущество для нас: можно экспортировать **только плечевой регион** из исходного Blender-атласа без глобального decimate и сохранить координатную совместимость с текущей Z-Anatomy моделью.

Ограничение: увеличение числа полигонов не устраняет возможные анатомические ошибки исходного атласа.

Статус: `candidate_hq_same_coordinate_system`.

## Z-Anatomy web GLB

Роль: текущий интерактивный прототип.

Плюсы:
- уже работает в браузере;
- структуры кликабельны;
- единая координатная модель;
- малый относительно исходника размер.

Минусы:
- существенная decimation;
- не прошёл нашу поструктурную анатомическую валидацию;
- CC BY-SA усложняет закрытый коммерческий сценарий.

Статус: `current_interaction_prototype`.

## BodyParts3D 4.0 / Human Atlas conversion

Роль: независимая контрольная координатная система и проверка структуры данных.

Плюсы:
- официальный BodyParts3D 4.0;
- единый целостный человек;
- богатая FMA/concept-структура;
- официальная база DBCLS сейчас CC BY 4.0.

Минусы:
- официальный downloadable mesh опубликован с polygon reduction rate 99%;
- Human Atlas дополнительно оптимизирует mesh для браузера;
- не является источником максимальной поверхностной детализации;
- сами авторы BodyParts3D предупреждают о возможных ошибках для образовательного использования.

Статус: `candidate_reference_geometry`.

## BodyParts3D / Anatomography 4.3 full-resolution candidate

Роль: кандидат на максимально подробную геометрию и детальную сегментацию мышц.

Сильная сторона для функциональной анатомии:
- отдельные части deltoid, trapezius и pectoralis major;
- отдельные головки biceps/triceps;
- отдельные мышцы rotator cuff и другие мышцы плечевого комплекса.

Проблемы:
- найденный pipeline получает данные через недокументированные Anatomography endpoints;
- происхождение и применимая лицензия конкретного downloadable набора требуют отдельного подтверждения;
- сторонний manifest нельзя слепо использовать как терминологический источник;
- полного отдельного набора капсулы/лабрума/основных плечевых связок и сухожилий в проверенном manifest не обнаружено.

Статус: `candidate_high_detail_pending_provenance_and_license_review`.

## AnatomyTOOL / Open3DModel

Роль: независимая региональная экспертная сверка.

Сильная сторона:
- материалы создаются и собираются в академической анатомической среде;
- есть отдельные региональные модели, включая rotator cuff;
- особенно полезно для проверки пространственных отношений и учебной адекватности.

Ограничение:
- это не одна универсальная координатная whole-body модель;
- лицензия проверяется для каждого отдельного материала.

Статус: `regional_validation_source`.

## Что сравниваем в интерфейсе сейчас

В опубликованном тесте доступен переключатель:

1. **Z-Anatomy web** — текущая рабочая модель.
2. **BodyParts3D 4.0 (контроль)** — независимая контрольная модель плечевого региона.
3. **BodyParts3D 4.3 full-res** отображается как кандидат, но не загружается в публичный интерфейс до разрешения вопроса происхождения и лицензии.

Следующий наиболее полезный кандидат для переключателя — shoulder-only экспорт исходной Z-Anatomy без сильного decimate. Он позволит отделить вопрос «качество исходной геометрии» от вопроса «потери при web-оптимизации».
