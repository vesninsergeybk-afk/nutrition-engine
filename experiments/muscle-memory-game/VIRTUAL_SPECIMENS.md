# Библиотека виртуальных анатомических препаратов

Виртуальный препарат — отдельная сущность, а не синоним учебного фильтра.

Каждый препарат задаёт:

- **question targets** — структуры, которые могут быть ответом в тренировке;
- **scene targets** — мышцы, которые должны остаться в анатомической сцене для честного топографического контекста;
- **context covers** — покровные/соседние мышцы, которые не обязаны быть учебными целями;
- **support bones** — костные ориентиры региона;
- **depth profile** — курированную рабочую карту мышечной глубины, если она уже есть;
- **default views** — ракурсы, с которых препарат разумно открыть;
- **padding** — запас пространства вокруг препарата при фокусировке камеры.

Это разделяет три разных задачи: тренировку, анатомическую сцену и навигацию.

## Принцип качества

Наличие препарата в каталоге не означает, что для него автоматически разрешена анатомическая команда «снять слой». Послойность включается только там, где существует отдельная курированная региональная карта глубины **и выбранный 3D-источник содержит достаточный обязательный набор мышц**. Пока такие рабочие карты есть для плечевого пояса, спины и переднебоковой брюшной стенки.

Рабочая карта глубины не равна статусу `verified_for_teaching` для самой 3D-геометрии. Геометрическая валидация ведётся отдельно по критериям `ANATOMY_QUALITY.md`.

Для остальных препаратов доступны изоляция, вращение, поиск и ручное скрытие структур; карта глубины добавляется отдельным анатомическим проходом.


## Межисточниковая полнота

Каталог препаратов не требует, чтобы Z-Anatomy и BodyParts3D содержали одинаковую детализацию. Общие мышечные концепты должны попадать в препараты одинаково, а отсутствие структуры в источнике фиксируется как ограничение источника.

Текущий показательный случай — переднебоковая брюшная стенка: Z-Anatomy даёт пять учебных целей, необходимых для рабочего профиля глубины, тогда как используемый BodyParts3D содержит только наружную косую как соответствующую учебную цель. Поэтому BodyParts3D помечается как `source-incomplete` для послойности этого препарата, а интерфейс не выдаёт неполную модель за полный анатомический стек.


## Пространственное окно препарата

Изоляция препарата теперь состоит из двух независимых механизмов:

1. семантический фильтр определяет, какие мышцы и костные ориентиры относятся к препарату;
2. вертикальное пространственное окно отсекает части длинных структур, выходящие далеко за его область.

Окно задано как доля полной высоты тела и поэтому переносится между двумя источниками 3D-данных без привязки к абсолютным координатам. Вращение камеры не меняет окно, потому что вращается наблюдатель, а не анатомическая модель.

Raycaster проверяет те же границы: визуально отсечённая часть мышцы не остаётся невидимой кликабельной целью.


## Аудит региональной анатомии — контрольная точка 2026-09-25

Проведены независимые контуры проверки:

1. **Состав препаратов и межисточниковая семантика.** Все 29 препаратов проверяются на Z-Anatomy и BodyParts3D; общие мышечные концепты не должны расходиться по принадлежности к препарату. Для компактных групп (ротаторная манжета, hamstrings, quadriceps и др.) закреплено ожидаемое количество целей.
2. **Послойность и «Глубже здесь».** Точечная подсказка допускает только подтверждённые отношения из регионального графа глубины, совпадающую сторону тела и реальное пересечение луча. Если точечное пересечение недоступно, поиск может показать более общий блок «Глубже относительно этой мышцы» — также только по проверенному графу.
3. **Переходы состояния.** Изоляция, повторный клик, смена препарата и смена источника не должны оставлять устаревшие кнопки глубины или рассинхронизировать кнопку «Показать окружение».
4. **Костный контекст.** Каждый препарат обязан иметь именованные костные ориентиры отдельно в Z-Anatomy и BodyParts3D. Для плечевого комплекса отдельно закреплены лопатка, ключица и плечевая кость.
5. **Пространственная изоляция.** Вертикальные окна дополнены адаптивным X/Z-ограничением по реальным границам учебных мышц. Мышцы, кости, кожа, соединительные и справочные слои, raycast и камера используют один и тот же 3D specimen box.
6. **Производительность и регрессии.** Отдельные проверки защищают от O(N²)-поиска, двойной перестройки региональной сцены и выбора кликабельной точки за пределами виртуального препарата.

### Известные ограничения

- BodyParts3D содержит только 1 из 5 необходимых мышечных целей брюшной стенки; полноценная послойность живота в этом источнике намеренно помечена как `source-incomplete`. Z-Anatomy даёт 5/5.
- Проверенные depth-профили пока есть для плечевого пояса, спины и переднебоковой брюшной стенки. Для шейно-воротниковой зоны, ягодичной области, бедра, голени и стопы послойность не должна изображаться как подтверждённая до отдельной анатомической валидации.
- Различия числа целей между источниками в сложных препаратах (например, глубокие мышцы спины и стопа) допустимы только как различия исходных моделей; общие концепты должны сохранять одинаковую семантику.


### Дополнение после разрушительного аудита

После контрольной точки дополнительно закрыты четыре класса регрессий:

- региональный crop переведён с вертикальной полосы на адаптивный **3D specimen box**: X/Z вычисляются по реальной геометрии учебных мышц, Y остаётся откалиброванным для каждого препарата;
- переключение ракурса сохраняет региональный фокус и больше не возвращает камеру к масштабу всего тела;
- русская терминология теперь сплошь проверяется отдельно для обоих источников: Z-Anatomy и BodyParts3D;
- «Глубже здесь» использует точечное пересечение только вместе с подтверждённым графом глубины; если точечная геометрия не даёт устойчивого пересечения, интерфейс может показать отдельно маркированные проверенные отношения «Глубже относительно этой мышцы».


### Финальный CI-контур

Финальная контрольная точка включает дополнительно:
- сплошную проверку русских названий всех мышечных частей BodyParts3D;
- сохранение регионального масштаба камеры при переключении анатомического ракурса;
- отсутствие дублирующих тяжёлых/сетевых проверок в fast-CI.


### Визуальная целостность препарата

Виртуальный препарат строится из **целых анатомических структур**. Пространственный box используется для кадрирования камеры, фильтра костного/контекстного окружения и определения области интереса, но не должен физически резать мышечные mesh плоскими clipping planes.

Следствия:
- у мышцы не должно появляться искусственного плоского «среза» только из-за выбора региона;
- вся видимая часть структуры остаётся интерактивной;
- смена препарата обязана сбрасывать выбранную ранее мышцу, строку поиска и блок «Глубже», чтобы название старой мышцы не оставалось в карточке нового препарата.


## Финальный принцип визуального препарата

Обычный виртуальный препарат **не режет мышечные mesh плоскими clipping-плоскостями**. Региональное окно используется как логическая граница для камеры, фокусировки, выбора и костного/тканевого контекста, а мышцы показываются целыми структурами. Это предотвращает визуально ложные «обрубки» мышцы на границе региона.

Послойность включается только для препаратов с проверенным depth-профилем. На текущей контрольной точке подтверждены: плечевой пояс, спина, переднебоковая брюшная стенка, ягодичная область, медиальная группа бедра, задняя поверхность бедра и задняя группа голени. Для смешанных топографических областей без надёжного линейного порядка слоёв интерфейс не должен имитировать такую последовательность.
