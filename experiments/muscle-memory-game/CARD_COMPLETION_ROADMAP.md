# План заполнения справочных карточек мышц

Актуально для ветки `feature/muscle-memory-mvp`.

## Критерий готовой карточки

Карточка считается законченной только если одновременно выполнены все пункты:

- есть русское и латинское название;
- проверены начало, прикрепление, направление волокон, действия и иннервация;
- есть `sourceNotesRu` там, где нужны функциональные, топографические или терминологические оговорки;
- указаны синергисты и антагонисты для тех движений, где их можно определить корректно; если прямого антагониста нет или связь зависит от положения сустава, это явно объяснено;
- есть хотя бы одна `asset-ready` иллюстрация, достоверно показывающая именно эту мышцу;
- 3D-сопоставление не подменяет отсутствующую структуру соседней геометрией;
- есть автоматическая проверка для спорных и легко ломаемых случаев.

## Очередь дальнейших проходов

1. **Голень и стопа.** Сначала завершить глубокую заднюю группу и тыл стопы, затем четыре подошвенных слоя. Для каждой мышцы добавлять отдельное или ясно подписанное региональное изображение.
2. **Голова и шея.** Не закрывать 44 структуры одной обзорной пластиной. Делить на функциональные и топографические группы.
3. **Внутренние мышцы головы и шеи.** Использовать изображения, где мелкие структуры подписаны или выделены; для гортани и языка избегать двусмысленных общих схем.
4. **Второй содержательный проход по уже иллюстрированным регионам.** Проверить `sourceNotesRu`, синергистов/антагонистов и позиционно-зависимые функции в спине, грудной клетке/животе, глазнице, верхней конечности и поверхностном тазовом дне.
5. **Финальный cross-region audit.** Автоматически проверить отсутствие пустых карточек, заглушек изображений, ложных 3D-алиасов, пропущенной иннервации и функциональных связей.

## Правило небольших проходов

Один рабочий проход — один связный анатомический блок примерно из 2–6 мышц. После него:

1. статическая проверка данных и лицензий;
2. fast-suite;
3. при необходимости один целевой browser-smoke;
4. только после зелёной проверки — fast-forward `release/static-atlas-v1`.

Это правило введено специально, чтобы не накапливать большой непроверяемый пакет изменений и не зависеть от длинных browser-smoke сценариев.
