# HOTFIX23 MEDIA ENTRY FIX — отчёт о проверке

## Причина исправления

В HOTFIX22 верхние карточки «По фотографии», «Записать голос» и «Аудиофайл» выполняли только навигационное действие: раскрывали блок ИИ и переводили фокус на нижнюю кнопку. Для запуска выбора файла или микрофона требовалось второе нажатие, о котором интерфейс не сообщал. Кроме того, медиамодуль Gemini находился в отложенном runtime-пакете, хотя верхние карточки появлялись уже в критической фазе загрузки.

## Реализованная архитектура

1. Верхняя карточка фотографии теперь синхронно передаёт исходный пользовательский клик скрытому файловому элементу. Системный выбор файла открывается одним нажатием.
2. Карточка записи голоса напрямую вызывает `startLiveRecording()` в рамках того же пользовательского жеста. Запрос разрешения микрофона появляется одним нажатием.
3. Карточка аудиофайла аналогично открывает системный выбор файла одним нажатием.
4. Медиамодуль `62-gemini-ration-import-v5.js` перенесён из отложенного runtime в критический shell. Обработчики доступны до окончания фоновой загрузки базы и вторичных функций.
5. Медиамодуль исключён из deferred-пакета, поэтому двойной инициализации нет.
6. Сохранены проверки отключённого состояния кнопок и штатные сообщения при отказе в разрешении микрофона.

## Браузерная проверка медиаввода

Проверка выполнена в Chromium на мобильном viewport 390 × 844.

- Карточка «По фотографии» одним нажатием открыла системный файловый диалог.
- Тестовое PNG-изображение было принято модулем и перешло в состояние `ready`.
- Медиамодуль был доступен уже после критической фазы, когда фоновая загрузка ещё не завершилась.
- Карточка «Записать голос» одним нажатием вызвала `getUserMedia()` ровно один раз.
- При тестовом отказе в разрешении показано корректное сообщение: «Доступ к микрофону не разрешён…».
- Состояние рекордера после отказа осталось безопасным: запись не активна, обработка не зависла.
- Ошибок JavaScript и ошибок консоли не обнаружено.

Результат: 2 из 2 функциональных сценариев пройдены.

## Повторная проверка FAST START

Пройдены шесть сценариев:

- мобильный штатный запуск;
- настольный штатный запуск;
- задержка фоновых пакетов на 2,5 секунды;
- отказ критического пакета с переходом на исходные модули;
- отказ единого пакета продуктов с переходом на 12 частей базы;
- отказ deferred-пакета с переходом на исходные модули.

Штатные результаты локального стенда:

- мобильный первый экран: 0,509 с;
- мобильная полная готовность: 1,314 с;
- настольный первый экран: 0,248 с;
- настольная полная готовность: 1,061 с;
- количество штатных запросов: 15.

При задержке фоновой загрузки первый экран появился за 0,213 с, полная готовность — за 3,492 с.

## Статическая и регрессионная приёмка

Пройдены 35 из 35 групп проверок, включая:

- согласованность версии HOTFIX23 в обоих index-файлах, selector, bootstrap и runtime-manifest;
- наличие медиамодуля в modern/legacy critical shell;
- отсутствие медиамодуля в modern/legacy deferred runtime;
- полноту разбиения runtime-источников;
- воспроизводимость сгенерированных пакетов;
- существование всех runtime-ссылок;
- 1105 продуктов и 1105 уникальных ключей;
- синтаксис активных JavaScript-файлов;
- синтаксис серверных PHP-файлов;
- 108 проверок реестра формул;
- 74 проверки нормативного реестра;
- 14 проверок навигационной оболочки;
- 12 проверок профиля и расчёта потребностей;
- 15 проверок контракта медиаввода HOTFIX23.

С HOTFIX22 побайтово сверены 496 защищённых файлов. Расчётное ядро, канонические продуктовые данные, API и CSS не изменены. Полезная нагрузка единого продуктового пакета также совпадает с HOTFIX22.

## Итог

Регрессия двухэтапного медиаввода устранена. Фото, запись голоса и выбор аудиофайла запускаются одним нажатием. Быстрый старт HOTFIX22 сохранён, расчётное ядро и база продуктов не затронуты.
