## Политика научного заполнения

- `SOURCE_REPORTED`: точное значение реального нутриента у **того же самого** идентифицированного вида/формы/состояния продукта в официальном источнике; сохранить код источника/выгрузки/нутриента/единицы.
- `CALCULATED`: только понятная химически и метрологически корректная формула из **известных компонент того же продукта**, с записью формулы и неопределённости. Не используется при произвольной имитации отсутствующих лабораторных данных.
- `SOURCE_REPORTED_ZERO`: ноль явно есть в источнике, не равен `MISSING`.
- `ASSUMED_ZERO`: структурное или технологическое предположение с маркировкой, не выдавать за измерение. Для подслащённых продуктов нельзя применять автоматически.
- `MISSING`: сохранять настоящую неизвестность; если движок научно корректно поддерживает неполные продукты, интерфейс должен показывать **неполное покрытие** и запрещать ложное «ноль» в микро- и HEI-выводах.
- Для HEI: FPID/FPED — пищевые эквиваленты, НЕ самостоятельный «балл» продукта. Статус exact присваивать только при точной идентичности; осмысленная реконструкция по официальной методике требует отдельных единиц/конверсии и ревью.
- Семейство из 89 не является доказательством производимой торговой марки РФ. Русские названия, состояния и aliases сверять с первичным описанием. Особенно осторожно с dry/cooked бобовыми, свежими/сушёными травами, видами рыб, цельнозерновой/рафинированной мукой, рафинированными/нерафинированными маслами.
- Исходные `main` 1 105 продуктов, все 12 оригинальных shards, вычислительные коэффициенты и регистры — замороженный эталон; import только через независимый новый staging и комплект regression tests.

4. Проверить лицензии, attribution, версии официальных таблиц. Разнести поля `source_record_id`, `source_dataset`, `source_version`, `method`, `review_status`. Не объявлять VERIFIED автоматически.
5. Перед единым подключением создать от свежего `main` единую интеграционную ветку, импорт через штатный генератор всех JSON/JS/gzip shards и manifest, без ручного исправления HTML. Пройти golden tests 1 105 эталонных записей, browser/desktop/mobile поиск по русским названиям, добавление порций, корректные микронутриенты, HEI и покрытие неизвестных, сохранение рациона, static Cloudflare gate и общий Quality Gate. 6. До успешного регресса **не объединять в `main` и не деплоить**. «Один релиз» означает единый контролируемый PR после прохождения доказательных и технических ворот, а не перенос сырых исследований.

### Проверка возможности масштабного числового восстановления

Создан `tools/benchmark_food_nutrient_imputation.py` с воспроизводимым seed 20261009: берёт исходную основную базу из 1105 ранее численно заполненных карточек, маскирует известные значения у 200 продуктов и пытается восстановить аналогами своей категории по БЖУ/названию. Этот эксперимент **не является независимой проверкой на лабораторных данных**, поскольку исходный каталог может содержать модельные значения.

- Для 179 исходных пропусков математическая модель смогла выдать лишь **93 числовые гипотезы** при ограничении «достаточно доноров своей категории»; они *НЕ внесены*, так как не выдержана научная пригодность метода.
- Внутренний контроль для **холина**: медианная симметричная абсолютная относительная ошибка 12,2%, 90-й процентиль **131%**. Для **витамина K** медиана 32,3%, 90-й процентиль **190,5%**. Для **селена** медиана 13,2%, 90-й процентиль **154,1%**. Значит, система иногда угадывает близко, но встречаются и критически большие ошибки. **Ни одна из 93 имитаций не может быть заявлена как измеренный нутриент или безопасная клиническая оценка.**
- Внутренний контур моделирования отметил всего 4 продукта в своей категории «специи» и 1 в категории «семена», то есть для них метод не обеспечивает надёжное научное восстановление; простой перенос из иных классов недопустим.
- [Imputation held-out benchmark (PASS as test, FAIL for general scientific authorization)](https://github.com/vesninsergeybk-afk/nutrition-engine/actions/runs/37860437856). `PASS` означает успешное выполнение программы, а не точность модели.
