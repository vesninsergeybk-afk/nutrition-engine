1. Исходная действующая база: **1 105 продуктов**, не изменена. В пилотной отдельной ветке PR #38 — ещё **16**, в `data-food-wave2-audit-20261009` отдельно подготовлены ещё **15** превью-карточек; один тимьян карантинирован.

3. В 56 заблокированных карточках **52** имеют хотя бы один незаполненный нутриент, **28** требуют достоверного HEI/FPID-сопоставления, **24** попадают в обе группы. Было **179 пропусков** 33-компонентного нутриентного профиля.
4. Проверены **реальные официальные** источники USDA SR Legacy 2018, Canadian Nutrient File 2026, USDA Foundation Foods 2026 (апрель), Food Patterns Ingredients Database 2017–2018; также осмотрен CoFID 2021 Великобритании.
5. **Одно новое значение доказательно восстановлено:** цельнозерновая полбяная мука (`Flour, spelt, whole grain`), **FDC 2003587**: `vitamin_b9_mcg=38.4` мкг фолатов (`Folate, total`, nutrient #417) на 100 г, напрямую из Foundation Foods 2026. Источник описывает получение как Analytical / derived from analytical (код A). Строгий автоматический тест подтвердил ID, имя, единицу, показатель, ненарушение остальных 55 карточек. Осталось **178 null-полей**, а данная карточка **всё ещё заблокирована**, поскольку у неё остались другие пропуски и нерешённое HEI-сопоставление.
6. CNF 2026: для **13/13** первичных канадских продуктов совпали официальные идентификаторы и названия, но среди отсутствующих нутриентных полей новых зарегистрированных значений нет.
7. USDA SR Legacy → CNF 2026: из **34** американских исходных профилей **19** совпали по NDB, нормализованному названию и основным макронутриентам; **14** различались официальными формулировками или деталями, **1** не относился к SR Legacy (FDC 2003587). Дополнительных безопасно подставляемых значений в 19 найденных не оказалось.
8. USDA FPID 2017–2018: **2 322** записи; для всех **28** неразрешённых сопоставлений проведён поиск. **0** точных совпадений на уровне нормализованного названия. Похожие продукты сохранены исключительно как подсказки для научной экспертизы. Никакие FPID-эквиваленты от похожих рыб, разных сыров, видов муки и обработанных кокосовых продуктов не переносились.
9. USDA Foundation Foods April 2026: **395** записей, точное исходное совпадение с 56 — одно (полбяная мука), одна подтверждаемая нутриентная величина (фолаты). UK CoFID 2021 осмотрен, но автоматическая проверка *строго точных* исходных имён не нашла совпадений; варианты по смыслу остаются предметом дополнительной ручной проверки.
10. В `research/external-food-v15/step4e-frozen` **постоянно закоммичены все 4 исходных доказательных файла** (32 preview, 56 blocked, 1 state-blocked, 1 report) с SHA256 в `research/external-food-v15/README.md`. Не зависим от истечения сроков артефактов GitHub Actions.
11. Патч на фолаты сохранён отдельно: `research/external-food-v15/verified-field-patches/spelt-folate-417-2026.json`; в общем workflow научный источник скачивается заново и независимо проверяется.

## Политика научного заполнения

- `SOURCE_REPORTED`: точное значение реального нутриента у **того же самого** идентифицированного вида/формы/состояния продукта в официальном источнике; сохранить код источника/выгрузки/нутриента/единицы.
- `CALCULATED`: только понятная химически и метрологически корректная формула из **известных компонент того же продукта**, с записью формулы и неопределённости. Не используется при произвольной имитации отсутствующих лабораторных данных.
- `SOURCE_REPORTED_ZERO`: ноль явно есть в источнике, не равен `MISSING`.
- `ASSUMED_ZERO`: структурное или технологическое предположение с маркировкой, не выдавать за измерение. Для подслащённых продуктов нельзя применять автоматически.
- `MISSING`: сохранять настоящую неизвестность; если движок научно корректно поддерживает неполные продукты, интерфейс должен показывать **неполное покрытие** и запрещать ложное «ноль» в микро- и HEI-выводах.
- Для HEI: FPID/FPED — пищевые эквиваленты, НЕ самостоятельный «балл» продукта. Статус exact присваивать только при точной идентичности; осмысленная реконструкция по официальной методике требует отдельных единиц/конверсии и ревью.
- Семейство из 89 не является доказательством производимой торговой марки РФ. Русские названия, состояния и aliases сверять с первичным описанием. Особенно осторожно с dry/cooked бобовыми, свежими/сушёными травами, видами рыб, цельнозерновой/рафинированной мукой, рафинированными/нерафинированными маслами.
- Исходные `main` 1 105 продуктов, все 12 оригинальных shards, вычислительные коэффициенты и регистры — замороженный эталон; import только через независимый новый staging и комплект regression tests.

## Подготовка к ОДНОМУ фронтенд-релизу

1. Собрать кандидатный dataset из уже проверенных 16 CORE + следующих 15 (всё ещё REVIEW_REQUIRED) + только научно разрешённых из 56 + отдельных dry-pinto и thyme после устранения семантических конфликтов. *Нельзя целиться в число 89 любой ценой.*
2. Для 178 пропусков приоритетно проверить **новые независимые** наборы (CoFID с ручным профильным сопоставлением, европейские таблицы, публикации по нутриентам по конкретным ингредиентам) и их единицы. Не допускать смены профиля на похожий без явной пользовательской карточки нового продукта.
3. По 28 HEI — ручное подтверждение точных продуктов/состояния или воспроизводимое использование официальных conversion factors. При научной неразрешимости — явно неизвестные HEI-эквиваленты и показ неполноты рациона; ни в коем случае молчаливый ноль.
4. Проверить лицензии, attribution, версии официальных таблиц. Разнести поля `source_record_id`, `source_dataset`, `source_version`, `method`, `review_status`. Не объявлять VERIFIED автоматически.
5. Перед единым подключением создать от свежего `main` единую интеграционную ветку, импорт через штатный генератор всех JSON/JS/gzip shards и manifest, без ручного исправления HTML. Пройти golden tests 1 105 эталонных записей, browser/desktop/mobile поиск по русским названиям, добавление порций, корректные микронутриенты, HEI и покрытие неизвестных, сохранение рациона, static Cloudflare gate и общий Quality Gate. Исторический общий gate падал ещё на baseline — причину исследовать отдельно от новых карточек.
6. До успешного регресса **не объединять в `main` и не деплоить**. «Один релиз» означает единый контролируемый PR после прохождения доказательных и технических ворот, а не перенос сырых исследований.
