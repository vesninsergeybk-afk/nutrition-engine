# Nutrient для Android — автономные расчёты и обновляемый каталог

Статус: **техническая альфа, не готова к распространению**.

Разрабатывается отдельно от публикации сайта. Основные файлы берутся только
из текущего репозитория: site/tools/nutrition/ и site/assets/.
Файлы расчётного ядра engine.js и fields.json переносятся в APK без
изменений. База продуктов берётся из зафиксированного файла сайта,
дополняется проверенными записями android/data/products-supplemental.json
и одновременно упаковывается в APK и публикуемый каталог.

## Что входит в эту альфа-архитектуру

- Локальная база продуктов, анкета, расчёты, HEI-2020 и сохранение рационов;
- локальный HTTPS-адрес WebViewAssetLoader, без подключения к сайту;
- постоянное хранилище WebView, импорт JSON через системный выбор файла;
- экспорт JSON через системный диалог Android;
- печать / «Сохранить PDF» через системный интерфейс;
- локальная модель ML Kit для **общих меток изображения**; подтверждение
  найденного продукта и ввод граммов выполняет пользователь;
- Интернет не нужен для входа, поиска продуктов, расчётов и хранения рационов;
- при наличии интернета только встроенный Android-загрузчик проверяет
  версии базы продуктов на GitHub (обычно раз в сутки или по кнопке);
- новые архивы проверяются по SHA-256, структуре записей, набору нутриентов,
  происхождению значений и сохранению всех прежних ключей продуктов;
- новый каталог включается при следующем запуске, старая версия остаётся
  доступной при сетевой ошибке; профиль, рацион и собственные продукты
  сохраняются отдельно от обновляемой базы.

APK запрашивает android.permission.INTERNET только для проверки каталога.
Удалённые страницы, код JavaScript и внешние ресурсы WebView по-прежнему
не загружаются. Запрос не содержит персональных данных пользователя.

## Источник версий и обновление каталога

Публичный стабильный канал: ветка `nutrient-catalog` репозитория
`vesninsergeybk-afk/nutrition-engine`, каталог `android/catalog/`.

- `latest.json` — небольшой указатель на актуальную версию, совместимость,
  количество продуктов и SHA-256 двух вариантов содержимого;
- `catalog-<sha256>.json.gz` — неизменяемый по имени сжатый снимок;
- первоначальные данные всегда в APK; если GitHub недоступен, программа
  продолжает работать со скачанной ранее или встроенной базой.

После проверки новых продуктов в зафиксированном источнике сайта или в
`android/data/products-supplemental.json` выполните из корня репозитория
`python3 android/tools/publish_catalog.py`, затем проверки ниже. Новые файлы
каталога необходимо опубликовать в ветке `nutrient-catalog`. Одного изменения
веб-сайта без обновления проверенного канала недостаточно.

**Текущее ограничение источника:** часть продуктов пока находится только в
дополнительном Android-файле. Чтобы сайт и APK показывали полностью одинаковый
набор, эти записи следует перенести в основной проверяемый каталог сайта и
убрать их из дополнения, сохранив ключи и сверив расчёты. Функция обновления
APK сама по себе не меняет публичный сайт.

## Что НЕ готово к полноценному выпуску

- локальное распознавание речи: нужен упакованный русскоязычный
  акустический модуль и проверка на широком круге устройств;
- распознавание смешанных блюд по фото: базовая модель меток не может
  восстановить рецепт, ингредиенты и граммы на уровне Gemini;
- реальные Android-тесты на устройствах, безопасность и стабильность
  WebView, включая после завершения работы и перезагрузки телефона;
- визуальная доводка мобильных экранов с пользователями;
- долговременный ключ подписи release APK нужно создать и хранить вне
  открытого репозитория, а затем внести в защищённые секреты GitHub Actions;
  пока ключ не настроен, CI выдаёт только debug APK, обновление которого
  поверх ранее установленного debug APK может быть невозможным.

**Не заявлять соответствие Gemini и «полный функционал» до проверки этих пунктов.**

## Сборка

Нужны JDK 17, Python 3, Android SDK 35, Gradle 8.11.1.

В корне репозитория:

1. python3 android/tools/package_web.py
2. python3 android/tools/publish_catalog.py --check
3. python3 android/tools/test_catalog_protocol.py
4. python3 android/tools/check_offline.py
5. cd android && gradle :app:assembleDebug

Артефакт: android/app/build/outputs/apk/debug/app-debug.apk.
Ветка разработки: feature/nutrient-catalog-sync-20261023.
Сайт в ветке production не изменяется.

## Обязательная приёмка перед первым публичным выпуском

- После установки включить режим полёта и выполнить весь сценарий:
  профиль → рацион → анализ → улучшение → отчёт.
- Сверить расчёты с эталонными случаями из исходного проекта:
  возрастные группы, разные нормы, клинические ограничения,
  смешанные блюда, HEI-2020.
- Закрыть приложение, открыть вновь, перезагрузить телефон,
  проверить сохранение и восстановление через JSON.
- Проверить PDF и системный выбор файлов; проверить поворот экрана,
  увеличение шрифта, экранную клавиатуру и доступность.
- На реальных фото отдельно измерить точность распознавания,
  долю ошибочных меток и время работы, не выдавать оценку массы
  или состава по изображению за установленный факт.
- Проверить наличие INTERNET permission, но отсутствие удалённой загрузки
  страниц, распознавания фото и пользовательских данных.
- Проверить кнопку обновлений в режиме полёта и при доступной сети;
  загрузку нового проверенного архива, отказ от повреждённого, сохранение
  всех прежних ключей, рациона и собственных продуктов при смене базы.
- Выпустить APK с постоянной подписью и обновить им установленную версию
  без удаления данных.
